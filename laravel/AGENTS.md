## What this is and why it exists

A rewrite of the KRYAcademia landing page and portal in Laravel 13 + Inertia 3 + React 19 on PHP 8.4. It exists because the hosting plan is PHP shared hosting with no Node.js runtime, so the original Next.js app cannot be deployed there. Nothing in this project may depend on a Node process running on the server: React is built to static assets on a developer machine, `QUEUE_CONNECTION` is `sync`, session and cache live in the database, and private files are served through a controller rather than `storage:link`.

The Next.js app is the migration **source**; this project is the **target**. `php artisan academy:import-legacy` reads the encrypted export it produces.

Deployment target: Hostinger shared hosting, MariaDB 11.8.9, preview domain `preview-kryacademia.krya.global`. Procedure: [HOSTINGER_DEPLOYMENT.md](HOSTINGER_DEPLOYMENT.md).

## Rules

- **Never run `migrate:fresh`, `db:wipe` or demo seeders against company data.** Seeders are limited to local and testing.
- **Never commit private data.** `storage/app/private/` holds teacher KTP images, encrypted snapshots and import archives; `database/*.sqlite` holds the imported company database. Both are gitignored — keep it that way, and never paste their contents into a chat.
- **`BACKUP_KEY` is the source export key, not `APP_KEY`.** Losing it makes every encrypted snapshot unreadable. Keep a copy off this machine.
- **Keep an existing `APP_KEY`.** Generate one only for a fresh installation that has never been used.
- **Imports preview first.** `academy:import-legacy` runs a preview; `--apply` refuses a target that already holds data. Never edit a manifest to make an import pass.
- **Document root points at `public/` only.** The backend, `.env`, `vendor`, `database` and `storage` stay outside it.
- **The PHP version is per hosting plan, not per subdomain.** Raising the plan to 8.4 moves the existing krya.global site too. Check that site first.
- Importer limits: 128 MiB per table, 256 MiB total payload, 1 MiB per file object.
